# VesselManualBot

RAG-система по судовой технической документации (Caterpillar marine engines и др.).

## Топология

- **Frontend:** Next.js 15 App Router на Vercel — ТОЛЬКО UI, без RAG-логики
- **Backend:** FastAPI на `trading-server` (Ubuntu, Ryzen 9 6000, 32 ГБ RAM)
- **Связь:** браузер → FastAPI напрямую через Tailscale (`tailscale serve`).
  Функции Vercel не находятся в tailnet и достучаться до сервера не могут —
  поэтому API routes для RAG не используются.
- **БД:** PostgreSQL 16 + pgvector, локально на сервере
- **Эмбеддинги:** `BAAI/bge-m3` (dense 1024 + sparse), CPU, torch float32.
  ONNX здесь НЕ используется и не планируется: sparse-голова требует
  кастомного постпроцессинга, готового экспорта в optimum нет, а эмбеддинг
  запроса занимает меньше процента времени — квантизовать нечего.
- **Реранкинг:** `BAAI/bge-reranker-v2-m3`, CPU, ONNX int8 (`RERANKER_BACKEND`).
  Это 99% времени запроса. torch-путь сохранён как эталон для сверки и отката.
  Выгрузка модели: `scripts/export_reranker_onnx.sh` (артефакт не в git).
- **Генерация:** OpenAI `gpt-4o-mini` — ТОЛЬКО финальный ответ

Дискретной GPU нет. Radeon 680M как ускоритель не используем: ROCm официально
`gfx1035` не поддерживает. Все модели на CPU.

## Конвенции (наследуются из formaink / mexc-trade-bot)

- pnpm, TypeScript strict, алиас `@/*` → `src/*`
- CSS Modules + CSS-переменные, темы day/night. **Tailwind не используем**
- Компонент: `components/Имя/Имя.tsx` + `Имя.module.css`
- Миграции: сырой SQL в `migrations/`, без ORM
- Валидация: Zod на фронте, Pydantic на бэкенде
- Backend: FastAPI + SQLAlchemy 2.0 + asyncpg, процесс-менеджер PM2

## КРИТИЧЕСКИЕ ПРАВИЛА ДОМЕНА

Это документация на судовые двигатели. Неверное число — риск для людей и техники.
Каждое правило ниже проверено на реальных страницах SEBU7844-37 и закрыто тестом
в `verify_chunks.py`. Нарушение любого из них — баг, а не стилистическая правка.

1. **Числа цитируются дословно.** Давления, моменты, зазоры, объёмы, номера
   деталей — только точная цитата с обеими единицами: `205 kPa (30 psi)`.
   Никакого пересчёта, никакого перефразирования.

2. **Извлечение текста только по колонкам** (clip-rect PyMuPDF).
   Наивный `page.get_text(sort=True)` на стр. 68 перемешивает шаги 1–2 с 8–10
   и роняет NOTICE в середину чужого шага. Это баг, а не косметика.

3. **Чанк = целая процедура.** Фиксированный размер чанка запрещён.
   Процедуры склеиваются через границы страниц и колонок
   (`Air Shutoff - Test` = стр. 68–70).

4. **Блоки WARNING/NOTICE никогда не отделяются от своей процедуры.**
   При разбиении длинной процедуры блок дублируется в каждую часть.
   Дублирование текста дешевле потерянного предупреждения.

5. **Варианты процедуры разделяются всегда, независимо от размера.**
   Если под подзаголовками идут собственные последовательности шагов —
   это разные варианты, и они обязаны стать разными чанками:
   - `Air Shutoff - Test` → ADEM II (5 шагов) и ADEM III (8 шагов)
   - `Coolant - Change` → `Flush` → Cat ELC (шаги 1–5) и Cat DEAC (шаги 3–9)

   Нельзя опираться на «нумерация начинается с 1»: Caterpillar нумерует
   второй вариант с тройки. Признак варианта — два и более подзаголовка
   одного уровня, под каждым из которых есть шаги.

6. **Таблица не разрывается.** Непрерывная серия строк целиком в одном чанке.

7. **Фильтр по модели двигателя и модулю управления — в SQL `WHERE`,**
   не в промпте. ADEM II ≠ ADEM III, модель не должна сама решать применимость.

8. **Grounding-проверка перед выдачей ответа.** Каждое число и номер детали
   из ответа обязаны присутствовать в извлечённом контексте. Не подтвердилось —
   не показываем.

9. **Ответ без ссылки на документ и страницу считается багом.**

10. **Честный отказ важнее правдоподобного ответа.** Если в документации нет —
    так и сказать, и отправить к дилеру Cat / Service Manual.

## Команды

```
make ingest F=path/to.pdf   # индексация одного PDF в JSON
make verify                 # прогон инвариантов чанкинга
make eval                   # golden set целиком: поиск + генерация
make eval-retrieval         # только поиск, без OpenAI — детерминирован, точен
make dev                    # uvicorn --reload + next dev
```
