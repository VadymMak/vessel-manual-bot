# Промпт для Claude в VS Code — Этап 2: RAG-ядро

Откройте папку `vessel-manual-bot` в VS Code и скопируйте всё, что ниже разделителя,
в чат Claude-расширения.

---

Прочитай `CLAUDE.md` и `README.md` в корне — там правила домена и результаты этапа 1.
Затем прочитай `ingestion/chunker.py`, чтобы понять структуру объекта `Chunk`,
и `chunks.json`, чтобы увидеть реальные данные.

Твоя задача — этап 2: RAG-ядро. Работает локально на Ubuntu-сервере, без облачной БД.

## Что построить

### 1. `migrations/001_init.sql`

Схема PostgreSQL 16 + pgvector. Таблицы `documents` и `chunks`.

`chunks` должна содержать все поля из dataclass `Chunk` плюс:
- `embedding_dense VECTOR(1024)` — bge-m3 dense
- `embedding_sparse SPARSEVEC(250002)` — bge-m3 lexical weights
- `context_prefix TEXT` — для contextual retrieval

Индексы: HNSW по обоим векторам, GIN по `applicable_models`, `smcs_codes`,
`part_numbers`, обычный по `maintenance_interval` и `control_module`.

### 2. `rag/embedder.py`

Обёртка над `BAAI/bge-m3`. Требования:
- **CPU, ONNX int8.** Дискретной GPU на сервере нет (Ryzen 9 6000, Radeon 680M,
  ROCm для gfx1035 официально не поддерживается — не пытайся использовать GPU).
- Возвращает и dense (1024), и sparse-веса за один проход модели.
- Ленивая загрузка модели: не грузить при импорте.
- Батчинг для индексации.

**Не используй OpenAI embeddings.** bge-m3 выбрана именно потому, что она
кросс-языковая: русский запрос ищет по английскому тексту напрямую, без шага
перевода. Перевод запроса в пайплайне отсутствует сознательно — он искажает
технические термины («зазор клапана» → «valve clearance», а в мануале «valve lash»).

### 3. `rag/loader.py`

Загрузка `chunks.json` → Postgres. Перед эмбеддингом добавь к каждому чанку
contextual prefix — 1–2 предложения от `gpt-4o-mini`, описывающие, частью чего
является фрагмент. Эмбеддится `context_prefix + "\n\n" + content`.
Кэшируй префиксы на диск: переиндексация не должна платить за них повторно.

### 4. `rag/retriever.py`

Гибридный поиск:
1. Жёсткий SQL-фильтр по метаданным (модель двигателя, `control_module`) —
   **в WHERE, не в промпте**. Это правило 7 из CLAUDE.md.
2. Dense top-50 (косинус) + sparse top-50 (inner product).
3. Слияние Reciprocal Rank Fusion → top-20.

### 5. `rag/reranker.py`

`BAAI/bge-reranker-v2-m3`, CPU, ONNX int8. top-20 → top-6.
Замерь время и залогируй: на этом железе ожидается 0.5–1.5 с.
Если медленнее — уменьши число кандидатов до 10, не жертвуй качеством иначе.

### 6. `rag/generator.py`

`gpt-4o-mini` через SDK `openai>=1.0`, со стримингом.

Системный промпт — словарь по локалям, как в `formaink/src/app/api/chat/route.ts`
(возьми оттуда структуру). Минимум `ru` и `en`. Правила в промпте:
- Отвечать ТОЛЬКО по предоставленным фрагментам
- Числа цитировать дословно, с обеими единицами: `205 kPa (30 psi)`
- Блоки WARNING/NOTICE выносить в начало ответа, до шагов, и по-русски,
  и в оригинале
- Шаги передавать полностью и в исходном порядке
- Каждое утверждение — со ссылкой `[SEBU7844-37, стр. 68]`
- Если ответа в документации нет — сказать прямо и отправить к дилеру Cat.
  Честный отказ важнее правдоподобного ответа
- Отвечать на языке вопроса, термины давать с английским оригиналом в скобках

### 7. `rag/verifier.py`

Grounding-проверка **без LLM**, на регулярках. Правило 8 из CLAUDE.md.

Извлечь из сгенерированного ответа все числа с единицами и номера деталей
(`\d{3}-\d{4}` и `\d[A-Z]-\d{4}`), сверить с извлечённым контекстом.
Неподтверждённое значение — блокировать выдачу и перегенерировать.
Верни структуру с перечнем неподтверждённых значений, чтобы это можно было
залогировать и потом посчитать метрику.

### 8. `rag/cli.py`

`python3 -m rag.cli "как очистить сердцевину охладителя"` — задать вопрос,
увидеть найденные чанки со скорами, ответ и результат grounding-проверки.
На этапе 2 фронтенда ещё нет, CLI — единственный интерфейс.

### 9. `eval/golden_set.yaml` + `eval/run.py`

Не менее 30 вопросов с проверенными ответами. Составь их **по реальному
содержимому `chunks.json`**, а не выдумывай. Обязательно включи:

| Вопрос | Ожидание | Что проверяет |
|---|---|---|
| Макс. давление воздуха при очистке aftercooler | 205 kPa (30 psi), стр. 68 | точность числа |
| Номер детали Hydrosolv 4165 | 1U-5490 | номера деталей |
| Как проверить air shutoff на ADEM III | 8 шагов, стр. 69–70 | **правильный вариант, не ADEM II** |
| Как промыть систему охлаждения с Cat DEAC | шаги 3–9 | **правильный вариант, не Cat ELC** |
| Момент затяжки форсунки | «нет в O&M, см. Service Manual» | **честный отказ** |

Последние три строки — самые важные. Метрики: точность чисел, полнота шагов,
корректность страниц, доля ложных «не знаю» и доля пропущенных отказов.

## Как работать

- Стек: Python 3.12, FastAPI придёт на этапе 3 — сейчас только библиотека и CLI
- Драйвер БД: `psycopg[binary]` версии 3
- Конфиг через `pydantic-settings`, переменные в `.env` (добавь `.env.example`)
- Никаких секретов в коде и в git
- После каждого модуля запускай `make verify` — этап 1 не должен сломаться

## Чего НЕ делать

- Не тащи Neon и `@neondatabase/serverless` — БД локальная
- Не добавляй Redis для rate limiting: 3–5 пользователей, FastAPI — один процесс
- Не добавляй Clerk/Auth.js: аутентификацией служит Tailscale
- Не меняй код в `ingestion/` без причины — он покрыт проверками и работает
- Не заменяй bge-m3 на OpenAI embeddings ради простоты

Начни с `migrations/001_init.sql` и `rag/embedder.py`, покажи их мне до того,
как писать остальное.
