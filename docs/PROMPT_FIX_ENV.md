## Шаг 1. Аудит — только чтение, ничего не менять

Собери полную картину. Что известно на входе:

- `python3` указывает на Python 3.7.9 (framework с python.org) — не подходит,
  в коде есть `@dataclass(slots=True)`, это 3.10+
- зависимости проекта ставились в Homebrew-питон
  `/usr/local/opt/python@3.11/bin/python3.11`
- есть conda, было создано окружение `vessel`
- поставились `transformers 5.14.1`, `FlagEmbedding 1.4.0`, `torch 2.2.2`

Проверь:

```bash
which -a python python3 python3.10 python3.11 python3.12 python3.13 2>/dev/null
conda env list 2>/dev/null
ls -d ~/.pyenv/versions/* 2>/dev/null
echo "PATH=$PATH" | tr ':' '\n'
```

Затем для КАЖДОГО найденного интерпретатора версии 3.10 и выше выполни проверку
и собери результат в таблицу:

```bash
"$PY" -c "
import sys, importlib.util as u
print('версия:', sys.version.split()[0])
print('путь:', sys.executable)
for m in ['click','psycopg','pgvector','pydantic_settings','yaml',
          'torch','transformers','FlagEmbedding','openai','fitz']:
    s = u.find_spec(m)
    v = ''
    if s:
        try:
            mod = __import__(m); v = getattr(mod,'__version__','')
        except Exception as e:
            v = 'ОШИБКА ИМПОРТА: ' + str(e)[:60]
    print(f'  {m:20} {\"есть\" if s else \"НЕТ\":6} {v}')
"
```

## Шаг 2. Отдельно проверь совместимость FlagEmbedding с transformers 5.x

Это главный риск. `FlagEmbedding 1.4.0` писался под `transformers` ветки 4.x,
а установлен 5.14.1 — мажорная версия с ломающими изменениями. Проверь реальным
импортом, а не предположением:

```bash
"$PY" -c "from FlagEmbedding import BGEM3FlagModel; print('импорт BGEM3FlagModel OK')"
"$PY" -c "from FlagEmbedding import FlagReranker; print('импорт FlagReranker OK')"
```

Если падает — зафиксируй точный текст ошибки, он определит решение.

## Шаг 3. Покажи мне результат и предложи ОДИН вариант

Формат ответа:

| Интерпретатор | Версия | Путь | Зависимости | FlagEmbedding импортируется |

Дальше — рекомендация с обоснованием и оценкой, сколько скачается заново
(pip кэширует колёса в `~/Library/Caches/pip`, так что повторная установка
тех же версий обычно идёт с диска, без сети — учти это в оценке).

Мой приоритет по вариантам, от лучшего к худшему:

1. **`.venv` в корне проекта** на базе найденного подходящего интерпретатора.
   Лучший вариант: VS Code подхватывает его автоматически, терминал активирует
   сам, `python3` внутри проекта становится однозначным, и conda/Homebrew/
   framework перестают путаться. Стоит одной установки, которая закрывает
   проблему навсегда.
2. Использовать Homebrew-питон напрямую, зафиксировав путь в проекте.
3. conda-окружение `vessel`.

Если считаешь иначе — скажи почему.

## Шаг 4. После моего подтверждения — выполнить

Установку делай **только в выбранный интерпретатор** и покажи, какой именно
`pip` вызываешь. Если решение — `.venv`:

```bash
"$CHOSEN_PYTHON" -m venv .venv
./.venv/bin/python -m pip install --upgrade pip
./.venv/bin/python -m pip install -r requirements.txt
```

Если импорт FlagEmbedding падал на transformers 5.x — сначала поправь
`requirements.txt`, заменив `transformers>=4.40` на `transformers>=4.40,<5`,
и только потом ставь. Не ставь сначала сломанную версию, чтобы потом откатывать.

## Шаг 5. Закрепить, чтобы не повторилось
