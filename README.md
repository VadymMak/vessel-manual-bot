# VesselManualBot — этап 1: ingestion

Извлечение и чанкинг PDF технической документации Caterpillar.
Проверено на SEBU7844-37 (3500B/3500C Marine Engines, 152 стр.) → **164 чанка**.

## Быстрый старт

```bash
pip install -r requirements.txt
python3 -m ingestion.cli manual.pdf --out chunks.json
python3 verify_chunks.py          # прогон инвариантов
```

## Что делает

| Модуль | Назначение |
|---|---|
| `ingestion/extractor.py` | Разбор страницы: колонки, заголовки, шаги, WARNING/NOTICE, таблицы, метаданные |
| `ingestion/chunker.py` | Сборка элементов в чанки-процедуры, разделение вариантов |
| `ingestion/pipeline.py` | PDF → чанки → JSON |
| `verify_chunks.py` | 5 проверок инвариантов на реальном документе |

## Три неочевидных факта об этих PDF

Всё проверено на страницах, а не предположено.

**1. Двухколоночная вёрстка ломает наивное извлечение.**
`page.get_text(sort=True)` на стр. 68 выдаёт шаги 1–2 вперемешку с 8–10,
а предупреждение о давлении 205 kPa падает в середину чужого шага.
Извлекаем колонки раздельно через clip-прямоугольники.

**2. Плашка WARNING — это изображение.** Слова «WARNING» в текстовом слое нет.
Детектируем баннер по геометрии (≈234×26pt), текст предупреждения —
идущие следом блоки, целиком набранные `Arial-BoldMT`.

**3. Границы процедур размечены самим Caterpillar.**
ID модуля вида `i08246330` (7pt) стоит перед каждым заголовком: 113 меток
на документ, 0 исключений. Это надёжнее эвристик по размеру шрифта.

## Главное правило чанкинга

Чанк — это **целая процедура**, а не N токенов.

Отдельно: **варианты процедуры разделяются всегда, независимо от размера.**
Если под подзаголовками идут собственные последовательности шагов —
это разные варианты, и смешивать их нельзя:

- `Air Shutoff - Test` → ADEM II (5 шагов) и ADEM III (8 шагов)
- `Coolant - Change` → `Flush` → Cat ELC (шаги 1–5) и Cat DEAC (шаги **3–9**)

Второй пример показывает, почему нельзя опираться на «нумерация начинается
с единицы»: Caterpillar нумерует второй вариант с тройки. Признак варианта —
два и более подзаголовка одного уровня, под каждым из которых есть шаги.

Без этого правила вопрос «как промыть систему охлаждения с Cat DEAC» вернул бы
чанк с обеими процедурами сразу, а метка типа ОЖ была бы от первого варианта.

## Проверки (`verify_chunks.py`)

```
OK  Последовательность шагов не разорвана
OK  Все WARNING документа сохранены
OK  WARNING привязан к своей процедуре
OK  Таблицы не разрезаны
OK  Корректные ссылки на страницы
```

Первая проверка — самая чувствительная: пропуск номера шага внутри чанка
означает, что процедура разорвана и часть шагов потеряна.
